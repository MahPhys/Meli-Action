# 📦 ملی اکشن — Meli-Action

**ابزاری مبتنی بر گیت‌هاب اکشن برای دور زدن فیلترینگ اینترنت — دانلود فایل از لینک مستقیم، یوتیوب، تلگرام، گوگل پلی، و ذخیره صفحات وب، همه از طریق سرورهای فیلتر نشده گیت‌هاب.**


---

## 🌐 چطور کار می‌کنه؟

گیت‌هاب اکشن‌ها روی سرورهای خود گیت‌هاب اجرا می‌شن که **توسط فیلترینگ اینترنت ملی ایران بلاک نشدن**. این پروژه از همین موضوع استفاده می‌کنه:

- **برای دانلود فایل:** ورک‌فلو با `curl` فایل را در runner دانلود و به آرشیو 7z تبدیل می‌کند؛ سپس آن را در ریپازیتوری یا یک GitHub Release ذخیره می‌کند.
- **برای آرشیو صفحات وب:** یک مرورگر بی‌سر Chromium (از طریق `playwright`) صفحه فیلتر شده رو کامل رندر می‌کنه، به فرمت MHTML ذخیره می‌کنه، زیپش می‌کنه و به ریپازیتوری پوش می‌کنه.
- **برای یوتیوب، تلگرام و گوگل پلی:** ورک‌فلوهای اختصاصی از ابزارها و سرویس‌های مستقل استفاده می‌کنند. خروجی معمولاً در `downloads/` و آرشیو MHTML در `download/` ذخیره می‌شود.

هیچ نرم‌افزاری نیاز نیست روی دستگاه شما نصب بشه. همه چیز در فضای ابری اجرا می‌شه.

## 🚀 شروع به کار

### مرحله ۱ — فورک کن

دکمه **Fork** رو در بالای صفحه بزن تا ریپازیتوری وارد حساب گیت‌هاب خودت بشه.

### مرحله ۲ — مجوز نوشتن اکشن‌ها رو فعال کن

ورک‌فلوها برای کامیت کردن فایل‌های دانلود شده به ریپازیتوری شما نیاز به مجوز دارن:

۱. توی ریپازیتوری فورک شده، برو به **Settings** ⚙️.
۲. از منوی سمت چپ، برو به **Actions → General**.
۳. زیر بخش **"Workflow permissions"**، گزینه **"Read and write permissions"** رو انتخاب کن.
۴. **Save** رو بزن.

> **همچنین**، زیر بخش **"Actions permissions"**، مطمئن بشو که **"Allow all actions and reusable workflows"** انتخاب شده.

> ⚠️ **امنیت:** مجوز نوشتن، کد ورک‌فلو و ابزارهای شخص ثالث را قادر به تغییر ریپازیتوری می‌کند. فقط ورک‌فلوها و لینک‌های مورد اعتماد را اجرا کنید و از ذخیره اطلاعات محرمانه در خروجی یا لاگ خودداری کنید.

### مرحله ۳ — یک ورک‌فلو اجرا کن

۱. به تب **Actions** توی ریپازیتوری خودت برو.
۲. ورک‌فلوی مورد نظرت رو از لیست سمت چپ انتخاب کن (مثلاً «دانلود از URL»، «دانلودر یوتیوب» و غیره).
۳. دکمه **Run workflow** رو بزن.
۴. پارامترهای لازم رو وارد کن (مثل URL، کیفیت ویدیو، پوشه خروجی).
۵. دکمه سبز **Run workflow** رو بزن.

بعد از اتمام اجرا، فایل دانلود شده توی پوشه مشخص شده توی ریپازیتوری قابل مشاهده‌ست. بعدش می‌تونی مستقیم از گیت‌هاب دانلودش کنی.

## ⚙️ جزئیات فنی

### دانلودر لینک مستقیم
از `curl` و `7z` استفاده می‌کند. برای انتشار در ریپازیتوری اندازه هر قسمت باید بین ۱ تا ۹۵ MiB و برای Release بین ۱ تا ۱۹۰۰ MiB باشد. برای استخراج چندقسمتی، همه قسمت‌ها را کنار هم قرار دهید و قسمت اول را با 7-Zip باز کنید. GitHub فایل‌های بزرگ‌تر از ۱۰۰ MiB را در Git عادی رد می‌کند؛ نگهداری فایل‌های بزرگ در تاریخچه Git اندازه clone را افزایش می‌دهد.

### آرشیوکننده صفحات وب (`save_as_mhtml.py`)
از کتابخانهٔ Python `playwright` برای راه‌اندازی یک نمونه Chromium بی‌سر استفاده می‌کنه، به URL مورد نظر می‌ره، صبر می‌کنه تا صفحه کامل لود بشه و بعد در فرمت MHTML ذخیره‌اش می‌کنه. آرشیو نهایی زیپ شده و به ریپازیتوری کامیت می‌شه.

### دانلودر یوتیوب
ورک‌فلوی پیشرفته از `yt-dlp` و ورک‌فلوی ساده از سرویس تبدیل شخص ثالث استفاده می‌کند و از انتخاب کیفیت (مثل ۷۲۰p، ۱۰۸۰p، فقط صدا) پشتیبانی می‌کنه. فایل `google_service.json` رو می‌شه توی v2ray ایمپورت کرد تا جستجو و مرور تامبنیل‌های یوتیوب در یک پروکسی ممکن بشه.

### دانلودر تلگرام
فقط کانال‌های **عمومی** تلگرام رو هدف قرار می‌ده. لینک پست به سرویس شخص ثالث `telegramdownloader.net` فرستاده می‌شود؛ این سرویس API رسمی تلگرام نیست و ممکن است تغییر کند یا در دسترس نباشد.

### دانلودر گوگل پلی
از `gplay-apk-downloader` استفاده می‌کند. این ابزار دیگر توزیع‌کننده توکن پیش‌فرض ندارد؛ قبل از اجرا یک توزیع‌کننده تحت کنترل خودتان را در secret ریپازیتوری با نام `GPLAY_DISPENSER_URL` تنظیم کنید. خروجی split به‌صورت آرشیو منتشر می‌شود؛ حالت ادغام تنها یک APK با امضای معتبر را می‌پذیرد. APK ادغام‌شده با کلید debug امضا می‌شود و ممکن است جایگزین نسخه رسمی نشود یا به‌روزرسانی نگیرد. ابزار بالادستی ممکن است نشانی dispenser را در لاگ چاپ کند؛ به لاگ‌ها دسترسی محدود بدهید.

---


### نکات مهم اجرا و حریم خصوصی

- لینک‌ها و محتوای قابل دانلود ممکن است برای سرویس‌های شخص ثالث قابل مشاهده باشند؛ از لینک‌های خصوصی یا دارای توکن استفاده نکنید. دانلودر ساده یوتیوب و تلگرام به سرویس‌های بیرونی وابسته‌اند و تغییر یا اختلال آن‌ها می‌تواند اجرا را متوقف کند.
- ورودی `extra_args` در دانلودر پیشرفتهٔ یوتیوب عمداً گزینه‌های قدرتمند yt-dlp (از جمله اجرای دستور) را می‌پذیرد؛ فقط ورودی مورد اعتماد را استفاده کنید.
- Spotify با `spotDL` فراداده را با یک منبع صوتی دیگر تطبیق می‌دهد، نه اینکه فایل اصلی Spotify را دریافت کند؛ کیفیت واقعی به منبع و محدودیت سرویس بستگی دارد.
- ورودی `zip_password` و کوکی ورودی محرمانه نیستند و ممکن است در تاریخچه یا لاگ اجرا دیده شوند. کوکی یوتیوب را به‌جای ورودی در secret به نام `YT_COOKIES` قرار دهید. برای آرشیوهای بسیار حساس به این ورودی رمز تکیه نکنید.
- مسیر خروجی باید نسبی، داخل ریپازیتوری و بدون اجزای مخفی یا `..` باشد. انتشار در Git فقط برای شاخهٔ انتخاب‌شده مجاز است، نه اجرای workflow روی tag. چند اجرای هم‌زمان ممکن است هنگام push با هم تداخل کنند؛ در صورت خطای non-fast-forward اجرا را تکرار کنید. برای Release، نام tag تکراری ممکن است دارایی‌های موجود را جایگزین کند؛ از tag یکتا استفاده کنید.
- برای `max_part_mb` در ورک‌فلوهای انتشار به ریپازیتوری حداکثر ۹۵ MiB مجاز است؛ در دو دانلودر تلگرام و یوتیوب پیشرفته مقدار صفر تقسیم را غیرفعال می‌کند، ولی فایل بیش از ۱۰۰ MiB همچنان قابل push نیست.

### اجرای تست‌ها

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install requests pyyaml
python -m unittest discover -s tests -v
python scripts/check_workflows.py
```

برخی تست‌ها به `ffmpeg`، `7z`، `zip` و `yt-dlp` نیاز دارند و در نبود آن‌ها رد می‌شوند. برای اجرای تست واقعی Chromium، ابتدا `python -m pip install playwright` و `python -m playwright install chromium` را اجرا کنید، سپس با `MELI_TEST_BROWSER=1 python -m unittest discover -s tests -v` تست بگیرید. CI این ابزارها و Chromium را نصب می‌کند. تست‌ها همچنین سرویس تلگرام را شبیه‌سازی می‌کنند و جایگزین اجرای واقعی ورک‌فلوها در GitHub و آزمودن سرویس‌های بیرونی نیستند.
